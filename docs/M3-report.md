## 3. Data contract used

The contract is adapted to the real Study 4 outputs (§28):

- **`sim/meta.json`:** season, engine description, the 9 metric names, the 4 research groups (chance creation, involvement, shooting volume, shot profile → metric indices), the **7 role names from the research's own role table**, windows, minimum minutes, and the case study's thresholds.
- **`sim/players.json`:** the search index, `[key, name, team, league, roleIndex, slug, {w1, w2, w3 minutes}]`.
- **`sim/r/<key>.json`:** one per player, `res[destination][window] = [[candidateKey, medianScore, minScore, robust, limitedEvidence] × 10]`, plus pool size, number of checks and a small-pool flag.
- **`sim/z/<league>_<window>.json`:** each profile's nine adjusted, role-standardised z-scores (≥ 900 minutes), used for drivers and comparisons.

## 4. Precomputed outputs consumed

**All results come from `src/study4/similarity.Engine` in the research project.** `scripts/build_similarity.py` imports and runs it with the case study's settings: windows w3, w2, recent2500, w1 × cosine/Euclidean = 8 checks.

- **Validated before the UI was built:** run from this repo, the engine reproduces `outputs/study4/bruno_serie_a_replacements.csv` exactly (top 15 players, scores and robust flags).
- **Coverage:** 1,914 players × 5 leagues × 3 windows, in about 3 minutes.
- **Ranking follows `Engine.find`'s own sort:** robust across the eight checks first, then the median score in the chosen window. Bruno → Serie A at 3 seasons gives **Samardžić, Dybala, Chukwueze** as strong profile matches, with no Bruno-specific code.
- **No model runs in the browser.** The browser only subtracts two published z-scores and labels the gap with Study 4's thresholds:
  - metric gap ≤ 0.5 SD: strong match;
  - ≤ 1.0 SD: moderate match;
  - larger: divergence;
  - a group is "closest" at a mean gap ≤ 0.5 SD, and "higher/lower" beyond 0.75 SD.
- **Removed:** the old in-browser engine (`js/s4_engine.js`) and its 392 KB `data/similarity.json`.

## 5. URL / share

- **URL format:** `?player=<slug>&league=<league-slug>&seasons=1|2|3`, plus `&compare=<slug>` for the compare view. Old `profile=3y` links still work.
- **Browser history:** each search and each compare adds a history entry, so Back returns to the results.
- **Copy link** copies the exact state.
- **Tested:** loading a shared result or compare URL rebuilds the same view; an unknown player shows "Player not found".
- **Share card** (Vercel Edge + `@vercel/og`): "Who plays like {player}? · {player} → {league} · Top comparable: {first result} · {n}-season profile · not a forecast". Rendered and checked locally; the page function also rewrites the title, description, `og:url`, `og:image` and Twitter tags.

## 6. Mobile

- **Phones (< 640 px):** a three-step wizard ("Step 1 / 3": player → destination → profile window → **Find similar**). Picking a player moves to step 2 automatically; Back buttons on each step.
- **Results:** stacked cards, group verdicts in a 2 × 2 grid, and compare rows with the metric name above both bars.
- **Tested:** 0 px overflow at 390 px.

## 7. Accessibility

- **Labels and announcements:** every control is labelled; "Select a player" is announced and linked with `aria-describedby`; results update in an `aria-live` region.
- **Compare view:** focus moves to its heading. The profile chart has a full text label, and the drivers are a real `<table>` with a caption.
- **Colour is never the only signal:** verdicts carry a word and a symbol (● ◐ ○), and both series are named in a legend.
- **Rest of the site:** 44 px tap targets, visible focus and reduced-motion support are unchanged. The automated pass over all 15 routes at 1440 / 390 is clean.

## 8. Performance

- **First visit:** about 59 KB compressed for the player index, then about 1.4 KB per player result and about 5 KB per league table.
- **Query time:** results render **1–4 ms** after clicking, measured in the page. That's well under the 500 ms target.
- **Size on disk:** 11 MB in total (1,914 player files) on static hosting.

## 10. Missing data / blockers / questions for PM

1. **Profile season.** The explorer uses **2025/26** profiles: the last complete season, the frozen Study 4 case study, and the only season where one-season profiles have enough minutes. The research also refreshes 2026/27 profiles weekly; using those would show current clubs but leave "1 season" mostly empty until midwinter. It's a single constant to switch (`SEASON` in `scripts/build_similarity.py`). Keep 2025/26?
2. **Match labels.** Study 4 defines "robust" but has no "strong/moderate profile match". The mapping used:
   - **Strong:** robust across the eight checks.
   - **Moderate:** not robust, but closer than 90% of the pool in the chosen window (the research's own 90% cut-off).
   - **Weaker:** otherwise.
   The per-metric labels map directly to the case study's similar / moderately similar / different. Approve this wording?
3. **Query-player minimum.** The research engine applies 900 minutes to the comparison pool; I also apply it to the searched player, which is the basis for "Not enough data". Agree?
4. **Two "chance creation" numbers.** In the compare view, Bruno's chance-creation group (3-season z-scores) is +2.8 SD; the Study 4 headline says 3.6 SD, which comes from the case study's separate chance-creation lens. Both are correct, but side by side they could confuse. Add a note?
5. **Player names are shown exactly as Understat spells them** ("Lazar Samardzic", "Matìas Soulè Malvano"). Correct accents only in the UI, or leave the data as is?
6. **Share previews still need a deploy test.** They're tested in Node only. Behaviour on Vercel (the rewrite with a query condition, Edge font loading) needs a preview-deploy check before it's relied on.
7. **The "Try the Transfer Calculator" link** passes the player and destination league. The calculator covers forwards and midfielders only, so some players won't be found there. Handled in M4.
8. **Rebuild steps.** The data needs the research project's Python environment:
   ```
   ~/dev/weather_football/.venv/bin/python scripts/build_similarity.py
   python3 scripts/build_similarity_page.py
   ```
   Not yet part of the weekly pipeline.
