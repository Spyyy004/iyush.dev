# 0. The product we're actually building

We are **not building a football portfolio**.

We are building:

> **A public football research lab that turns rigorous analysis into an intuitive, interactive experience.**

The site should establish three things simultaneously:

### To a football fan
> "This is fascinating."

### To a football analyst
> "This person understands the problem."

### To an engineer/recruiter
> "This person can actually build the system."

That third layer is particularly important because the parent site already establishes Ayush as an AI Product Engineer who builds and ships products. [iyush.dev](https://www.iyush.dev/)

The football site should therefore **extend the existing identity**, not compete with it.

# 3. Research foundation

The frozen research dataset covers:

- 5 leagues
- 2015/16–2024/25
- 18,011 matches
- 8,348 players
- 525,328 player-match observations
- ~452,000 shots

Live seasons are maintained separately and don't alter frozen results. Football Research Series — Fina…

The research progression is:

| # | Study | Question | Product role |
|---|---|---|---|
| 01 | Environment | Does weather/crowds change performance? | Establish context |
| 02 | Home Advantage | Does home advantage belong to players? | Separate player from venue |
| 03 | Opposition | How much does opponent quality distort stats? | Context-adjust player output |
| 04 | Similarity | Can we find similar players? | Discovery tool |
| 05 | Transferability | What survives a league move? | Decision tool |

The final study is the culmination: Study 4 similarity is explicitly tested as a predictor in Study 5 and adds no predictive improvement. Football Research Series — Fina… Football Research Series — Fina…

This progression **must drive the site's information architecture.**

# 23. Animation principles

### Use animation for:

- state changes
- data transitions
- filtering
- chart construction
- comparisons

### Avoid:

- decorative particles
- constant movement
- excessive parallax
- gratuitous 3D
- football clichés

The feeling should be:

> **calm, precise, intelligent**

not:

> sports betting website.

# 25. Accessibility

M0 requirements:

- keyboard navigable
- visible focus states
- semantic HTML
- sufficient contrast
- charts accompanied by textual summaries
- colour never the only signal
- reduced-motion support
- minimum 44px touch targets

---

# 26. Performance requirements

The research dataset should **never be downloaded wholesale by the browser**.

Use:

- precomputed outputs
- static JSON where appropriate
- server-side/API queries where needed
- lazy-loaded visualisations

Target:

### Homepage

Fast initial render.

### Tools

Fast perceived response.

If a calculation takes time:

```text
Analysing 3-season profile...
```

rather than an empty spinner.

# 29. What the coding agent is NOT allowed to do

This is important enough to put directly in the future coding-agent PRD.

### The agent must NOT:

- invent research findings
- modify statistical results
- invent metrics
- invent player data
- create fake confidence intervals
- change model outputs for visual appeal
- fabricate missing information
- redesign the information architecture without approval
- build all milestones at once
- add unnecessary dependencies
- turn the site into a generic dashboard
- use stock football imagery everywhere
- introduce gradients/animations merely for visual flair

### The agent MAY:

- implement approved designs
- create reusable components
- optimise rendering
- suggest implementation improvements
- identify technical issues
- propose UX improvements

But **PM approval is required for scope/design changes.**
