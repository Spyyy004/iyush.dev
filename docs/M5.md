# M5 — Live Research Tracker

## Product goal

Answer: **Does the research still hold when new football seasons happen?**

The frozen research remains the scientific baseline: **2015/16 → 2024/25**. The live layer then asks: What happened in 2025/26? What is happening so far in 2026/27?

The crucial principle: **Live data never rewrites the frozen research.** It sits beside it.

---

# 1. Why M5 now?

We've built: M2 What did we discover? · M3 Who plays like him? · M4 What happens if he moves? Now: **M5 Is the underlying effect still happening?** That gives the product a temporal dimension. It also creates a reason for someone to **come back next month**.

# 2. Route

`/football/live`. Navigation: RESEARCH · TOOLS · LIVE (active) · METHODOLOGY. Give `LIVE` a very subtle red indicator. Not a flashing "LIVE!!!".

# 3. Hero

**Does the research still hold?**

Subheading: "The original analysis is frozen. New seasons are added separately to see whether the patterns continue."

Then: FROZEN BASELINE 2015/16 — 2024/25 · LIVE 2025/26, 2026/27. This distinction should appear **above every live chart**.

# 4. Frozen vs Live

This is the core visual language. Every live metric should use FROZEN · 2025/26 · 2026/27 rather than mixing all seasons into one chart.

```text
HOME xG EFFECT          OPPONENT EFFECT
Frozen   +26.6%         Frozen   −13.8%
2025/26  +27.1%         2025/26  −11.4%
2026/27  +21.0%         2026/27  −12.9%
```

These are already validated research values.

# 5. First Section — Home advantage

Headline: **The home edge is still there.** Hero metric: +27.1% (2025/26). Comparison: Frozen +26.6% · 2025/26 +27.1% · 2026/27 +21.0%. Interpretation: "The 2025/26 home xG effect was almost identical to the frozen historical estimate. The early 2026/27 estimate is lower, but remains positive." Don't overinterpret 2026/27. It is explicitly early.

# 6. Second Section — Opposition

Headline: **Stronger opponents still suppress output.** Frozen −13.8% · 2025/26 −11.4% · 2026/27 −12.9%. Then: "The direction and approximate magnitude remain consistent with the historical estimate." Again, avoid claiming the model has been "proven."

# 7. Confidence / Sample Status

Live research needs a different visual language from frozen research. Every live result should include STATUS: ● COMPLETE · ● CURRENT · ● EARLY. For example 2025/26 `COMPLETE`, 2026/27 `EARLY SEASON`. A number from five matches should not visually carry the same authority as a ten-season result.

# 8. Season Progress

```text
2026/27
SEASON PROGRESS  ████████░░░░░░░░
Matches processed  XXX
Last updated       06 Oct 2026
```

The actual values must come from the live pipeline. Do not hardcode.

# 9. "What Changed?"

**What's changed since the baseline?** HOME xG +26.6% → +21.0% Slightly lower · OPPOSITION −13.8% → −12.9% Broadly stable. Use language: broadly stable · higher · lower · early · insufficient evidence. Avoid "Home advantage has collapsed." unless the underlying evidence actually supports that.

# 10. Historical Context

Expandable **Show historical seasons**: 2015/16 +XX% … 2024/25 +XX% ── FROZEN +26.6% · 2025/26 +27.1% · 2026/27 +21.0%. Much more interesting than simply comparing three numbers.

# 11. Player-Level Checks

The research found: past home edge does not predict future home edge (r = .011), and overall adjusted player level predicts elite-opponent output better than past elite-opponent record. Could become a small "research continues to hold" card — **but only expose it if the live pipeline actually calculates the updated version.** Don't imply we have a 2026/27 version if we don't.

# 12. Research Status Board

```text
01 Environment      ◐ Weather freeze pending

03 Opposition       ● Confirmed
04 Similarity       ● Confirmed · ◐ Known-pairs check pending
05 Transferability  ● Confirmed · ◐ League-effect improvement planned
```

Unusually transparent; shows research is an ongoing process.

# 13. Open Questions — What's next?

- **Temperature:** Does temperature have a meaningful effect once the five-league weather analysis is frozen?
- **Similarity validation:** Do known similar-player pairs behave as expected?
- **Transfer model:** Can a percentage-based league effect improve predictions for low-output midfielders moving into the Premier League?

These come directly from the research's outstanding items. Don't invent more just to fill the section.

# 14. Update Log

Small timeline (e.g. "06 OCT 2026 2026/27 data updated · 30 SEP 2026 2025/26 season finalized · 23 SEP 2026 Transfer model validation updated"). **Only show events that actually exist in the pipeline.** Purpose: **This thing is maintained.**

# 15. Data Provenance

Bottom of page: LIVE DATA · Updated weekly · Frozen baseline 2015/16 — 2024/25 · Current seasons 2025/26, 2026/27 · Sources: Understat, football-data.co.uk, Open-Meteo ERA5 … Use the same source/provenance component from M2.

# 16. Visual Treatment

Subtly different from Research. Research: quiet / editorial / narrative. Live: **precise / operational / current** — an instrument panel, still within the same design system. Don't turn it into Bloomberg.

# 17. Live Indicator

Small status element: "● LIVE DATA · UPDATED WEEKLY". No animation. A static dot is enough.

# 18. Chart Behaviour

Frozen / 2025/26 / 2026/27 rows. The frozen baseline should be visually distinct. The current season gets emphasis. **Don't use red simply because something is current.**

# 19. Mobile

HOME ADVANTAGE · Historical baseline +26.6% · 2025/26 +27.1% · 2026/27 +21.0% · Interpretation … then next metric. Don't cram three-column desktop cards into mobile.

# 20. "Last Updated"

Extremely visible at the top: LAST UPDATED 06 OCT 2026 · 14:00 IST. Actual timestamp should come from the pipeline. Don't manually maintain it.

# 21. Data Architecture

The live page should consume a generated snapshot.

```typescript
type LiveSnapshot = {
  generatedAt: string
  seasons: { id: string; status: "frozen" | "complete" | "current" | "early"; progress?: number }[]
  metrics: LiveMetric[]
  researchStatus: ResearchStatus[]
}
type LiveMetric = {
  id: string; label: string
  frozen: { value: number }
  seasons: { season: string; value: number; status: string }[]
  interpretation: string
}
```

The actual structure should follow the existing pipeline outputs. **Do not make the frontend scrape Understat or run the research pipeline.**

# 22. Data Update Architecture

Ideal: Weekly pipeline → Validation → Generate live snapshot → Store snapshot → Website consumes snapshot. Not: Visitor → Website → Understat → Run analysis. Absolutely not.

# 23. Failure States

- **Pipeline stale:** "DATA MAY BE STALE · Last successful update: 06 Oct 2026 · The latest season data is not currently available."
- **Partial update:** "PARTIAL UPDATE · 2026/27 data is still being processed."
- **Missing metric:** don't show `—` with no explanation. Say: "Not yet available for this season."

# 24. Methodology Connection

Bottom: **How is this calculated?** → Methodology. And **Why keep the original dataset frozen?** — "Freezing the historical dataset prevents new data from silently changing previously published findings."
